# iPhone Excel 清晰度调整

2026-11-14，独立体验 Host，iPhone 客户端继续使用构建 31。

## 原因与修改

500×1015 点的竖屏 Excel 原先等比放入 2560×1440 横屏编码画布，有效内容约 709×1440 像素。客户端去黑边后将这部分内容铺到手机，源端已经丢失的文字细节无法恢复。

启用 mobile-window-layout 的 Host 现在按已选窗口的 SCContentFilter.contentRect 和 pointPixelScale 构造采集画布，并启用 best 捕获分辨率。RTCVideoSource 同步使用同样尺寸。上限为原 preset 的像素预算和单边 4096；尺寸取偶数，避免 4:2:0 编码要求导致失败。未启用移动窗口布局的 Host 保留固定画布行为。

本机 Retina 比例为 2：竖屏实际接收 1000×2030，横屏 1628×860。竖屏窗口有效像素数约为原来的 1.99 倍；传输总画布从约 369 万像素减为 203 万像素。此比例是像素数改善，不是主观清晰度评分。iPhone 屏幕仍有一次缩放，未宣称达到屏幕原生逐像素对应。

## 验证

- `.build/ios-sharpness-review/retina34.xcresult` 真机 Excel 操控回归通过：单元格点击、中文和表情读回、滚动、旋转后点击。
- `evidence34/` 四份元数据确认实际解码尺寸，显示失败 0，输入错误为空；`verified-dimensions.json` 保存完整结果。
- 28 项模拟器原生测试通过，包含 Retina 尺寸、旋转、预算限制、偶数边长及非法参数；2,115 项几何断言通过。
- 独立 Host 编译通过；正式通信 Host PID 86689 未重启，原 45990/45991 端口与参数保持不变。

本轮没有提高码率，没有增加锐化滤镜，没有改变手机背景填充或触摸坐标定义。编码仍为 HEVC Main10 PQ，iPhone 继续默认桌面颜色显示。键盘出现时缩小完整窗口的问题另行完善。
