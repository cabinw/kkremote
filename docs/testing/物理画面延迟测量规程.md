# T06：物理画面延迟测量规程

状态：方法已整理，物理采样未完成。当前只有 Host、iPhone 和 USB 投屏路径，没有已布置的独立同步光学采样。不能从软件队列统计推导端到端 P95。

## 测量对象

测 source-to-photon：Mac 显示器上选定窗口的视觉事件首次可见，到 iPhone 显示器同一事件首次可见的时间。它包含两块屏幕不同扫描相位与像素响应。输入到显示的 input-to-photon 属于远端输入真正接通后的另一项测试。

两块屏幕必须同时出现在同一个独立相机画面。至少 240 fps，关闭插帧、自动慢放和可变帧率转换，固定曝光并保留原始帧时间戳；画面中同时保留设置 / 网络条件的旁证。相机不能就是当前接收视频的手机。USB 镜像不作为接收屏幕。

## 固定条件

- 2560×1440 / 60 fps / 20 Mbps 预算，记录实际有效载荷、HEVC/H.264、HDR/SDR、版本、source 逻辑尺寸和实际显示刷新率。
- 采用同一位置的高对比块变化和递增可读事件编号。事件间隔 300–700 ms，避免与 60 Hz 恒定锁相；每次只测选定的同一水平区域。
- 保持源窗口持续前台绘制，手机 App 在前台；记录 ProMotion / 固定刷新率、亮度、温度、低电量状态及网络。固定刷新率是测量条件，不擅自更改用户系统设置。
- LAN 和蜂窝 Ponte 分别采集，Ponte 外层是否 relay 无证据时标未知。每种配置至少 300 个事件，建议 1000 个以更稳健估计 P99，启动阶段单列。

## 逐事件判读

对每个 ID 标记源屏最后旧状态帧 `s0`、首次新状态帧 `s1`，接收屏同样标记 `r0`、`r1`。以相机记录的真实时间戳计算区间：

`latency ∈ [time(r0) − time(s1), time(r1) − time(s0)]`

中点只作为估计值，保留区间宽度。240 fps 的理想采样周期约 4.17 ms；两次阈值判断的区间宽度通常可达约 8.33 ms，另有曝光、滚动快门、屏幕扫描和判读阈值误差。HDR 高光应避免过曝，否则阈值改变会扭曲结果。

不能仅挑选清楚、低延迟的事件。缺帧、模糊、编号不可读均计数并说明排除原因；网络冻结导致跳过的事件单独记录为未呈现。对有效事件报告 P50 / P95 / P99、最大值、样本数、排除数，以及统计方法（nearest-rank）和原始 CSV。

CSV 列：`run_id,event_id,source_old_frame,source_new_frame,receiver_old_frame,receiver_new_frame,lower_ms,upper_ms,midpoint_ms,valid,exclusion_reason`。不要记录私有窗口内容或输入文本。

## 通过规则

先按实测分布描述支持范围，再讨论目标。LAN P95≤80 ms 是待验证目标，不直接套用到蜂窝。软件诊断同时保存，用于解释某次尖峰所在阶段；它不能代替物理采样，也不能把不同阶段的 P95 相加当端到端 P95。
