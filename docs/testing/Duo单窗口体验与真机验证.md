# Duo 单窗口、桌面与真机验证

Duo 工作区上方显示远端画面，下方保留快捷键和独立触控板。外屏竖持时，Dock、桌面、键盘、会话和设置由系统排在右侧固定栏。最近访问的应用也以图标留在固定栏里，竖持最多两个，高度紧凑时一个。完全展开和竖向书本姿态继续使用触摸工作区。[Apple 的 Duo 工具栏说明](https://developer.apple.com/videos/play/tech-talks/111462/)

## 已实现的工作区

- UIKit 在支持铰链状态的视图上通过 `UIHingeInteraction` 识别 Duo。其他设备也可以在连接设置中打开「使用 Duo 触控板布局」。Dock 按应用分组，只展示有可选窗口的 Mac 应用图标。轻点单窗口应用可立即切换；多窗口应用再按标题选择。Host 按请求随目录发送每个应用的一份小尺寸 PNG，预算受现有信令帧上限约束。旧 Host 未提供图标时使用应用名首字占位。
- 单窗口使用 ScreenCaptureKit 的独立窗口过滤器。Duo 的触摸布局将画面放在系统安全区域内，再留 6 pt 边距，保留源窗口边缘。触控板使用同一套源坐标换算移动与点击。标题栏、标签和应用内工具栏随该窗口串流。macOS 全局菜单和独立弹出窗口属于其他捕获表面，目前可通过桌面入口访问。
- 「桌面」需要 Host 启动时显式打开 `--share-main-display`。客户端请求桌面目录项，用户确认后才切换到物理主显示器。窗口和桌面共用已经配对的信令与媒体通道。切换时先清理上一来源的输入队列和授权，随后为新来源建立媒体会话。单窗口仍按窗口选择，整个过程无需启动虚拟显示器或调整 Mac 窗口布局。
- 触控板支持单指移动本地指针、轻点点击、双指轻点右击和双指滚动。桌面点击和滚动需要 Host 的辅助功能权限及 `--mobile-window-control`。半展开键盘可向所选窗口发送按键和组合键。看桌面时，先点上屏的输入窗口，再使用下屏键盘。滚动沿用现有发送节奏，Sill 式惯性列为下轮对照。

### 半展开键盘

设备报告半展开，并且 SwiftUI 当前视图内的活动折痕为横向时，使用笔记本布局。上屏从玻璃顶边开始，按宽度等比显示选中的应用窗口或物理桌面，左右贴边。宽画面的余量留在折痕上方。高窗口可在画面上双指上下平移，或在触控板上移动指针查看下方内容。下屏依次排列操作菜单和六行美式 Mac 键盘。画面可延伸至折痕中心，菜单和键盘仍在折痕下界之外。左侧固定 App 选择按钮，中间横排显示当前桌面上有可共享窗口的全部应用，左右滑动可浏览。右侧依次是键盘／触控板切换、物理桌面、会话和设置。切换输入方式时继续观看原窗口。[Apple 关于折痕区域的说明](https://developer.apple.com/documentation/uikit/uiview/reservedregion)

Host 从 macOS Dock 读取应用顺序，与当前窗口目录取交集。同一个 App 的多个窗口共用图标，轻点后按窗口标题选择。目录内其余应用按名称追加。旧 Host 或未授权读取 Dock 时，客户端按名称排序。连接期间 Host 每三秒检查可见窗口集合，仅在集合变化时通知 Duo 更新目录。[Apple 的 Dock 应用辅助功能角色](https://developer.apple.com/documentation/applicationservices/kaxapplicationdockitemsubrole)

键盘提供 Esc、F1–F12、数字和标点、字母、修饰键及方向键。轻点修饰键后再点目标键，可输入组合键。Caps Lock 持续生效，再点一次解除。Fn 配合方向键可发送 Home、End、Page Up、Page Down，Fn 配合退格发送向前删除。按键通过已经获准的控制会话传给 Mac，输入法和快捷键由 Mac 处理。使用旧 Host 时，完整键盘会等待 Host 升级。

桌面输入以最近一次在上屏点中的 AX 窗口为目标。Host 逐次验证当前显示器、控制租约、前台应用、焦点窗口及按键序号。切换来源后需要重新点选输入窗口。

### 复现窗口和桌面点击

1. 启动已配对、具有录屏和辅助功能权限的本地控制 Host。在原有启动参数后增加 `--share-main-display`，保留物理窗口捕获和原有连接设置。Duo 客户端连接该 Host 的局域网地址。
2. 从仓库根目录执行以下命令，保持测试窗口打开。它位于物理主屏中心，记录每次收到的鼠标按下。第一次点击后它会短时置顶，供桌面模式点击同一目标。

   ```sh
   mkdir -p .build/duo-check
   xcrun swiftc Tests/DuoClickFixture.swift -o .build/duo-check/DuoClickFixture
   .build/duo-check/DuoClickFixture .build/duo-check/click.count
   ```

3. 使用 `Apps/IOSInteractionLab/device-project.yml` 生成设备测试工程，选择已签名的 Duo，在 Xcode 中单独运行 `DuoWorkspaceTests.testPhysicalWindowAndDesktop`。也可在 Duo 上依次操作「Dock → 测试应用图标 → 轻点触控板 → 桌面 → 显示完整桌面 → 轻点触控板 → 右栏测试应用图标」。新启动的计数器应显示 2。再次启动计数器时在命令末尾追加 `--two-windows`，可验证同一应用的两个窗口只占用一个图标，展开后按标题选择。
4. 将 Duo 像笔记本一样半开，使折痕横向，重新启动计数器，单独运行 `DuoWorkspaceTests.testFoldKeyboardWindowAndDesktop`。测试用例核对区域位置和输入回执，Mac 端可在计数器旁的 `.keys` 文件核对实际收到的虚拟键码与修饰键。
5. 单独运行 `testFoldDockFollowsWindowLifetime` 可验证图标随窗口增减。通过 xcodebuild 设置环境变量 `TEST_RUNNER_DUO_TEST_LIVE_DOCK=1`，开始时关闭测试应用。观察到 `FOLD_WATCH_READY` 后启动上述测试应用，出现 `FOLD_WATCH_OPEN` 后关闭它，等待 `FOLD_WATCH_CLOSED`。
6. 自动化分别核对选中的来源、解码就绪、呈现入队、渲染失败数及输入回执。测试窗口截图、原始报告和设备配置留在本地。几何回归可执行 `bash scripts/test-ios-viewport.sh`，本次通过 2,407 个断言。

### 单窗口边角与输入

1. 先定位裁切层。用两角带编号按钮、四边有标记的合成窗口，对照源窗口、解码画面和实际屏幕。现有 iPhone 渲染会对选中窗口按源坐标约 20 pt 加圆角遮罩。分别检查源内遮罩、iOS 安全区、显示缩放以及设备的物理圆角，记录消失的第一个环节。源内遮罩剪掉的按钮要先修遮罩；手机截图也需与真机可见范围对照。[窗口渲染](../../Apps/TransportLab/Sources/IOSLabView.swift) · [既有圆角验证](iPhone正式链路界面接入.md)
2. 在当前视频容器坐标内求有效安全矩形，扣除外层已经留出的边距。窗口已完整可见就沿用原布局。有余量时优先最小平移；平移仍会遮挡时等比缩小，像素精确模式同步复核。折叠、旋转、键盘和文本焦点变化时重算。首轮按实测屏幕尺寸与安全区布局；没有稳定姿态信号时用显式触控板入口。
3. `ViewportGeometry` 统一产生内容矩形，视频、光标、点击、拖动和文字定位共用同一正反变换；安全边距内的触点不发送给 Host。窗口切换期间按窗口代次丢弃陈旧输入。对于编码前已经缺失的弹出菜单，单独验证随窗口出现的附属界面。[视口几何](../../Apps/TransportLab/Sources/MobileInteraction/ViewportGeometry.swift) · [渲染容器](../../Apps/TransportLab/Sources/MobileInteraction/MobileViewport.swift)
4. 仅当完整窗口方案明显损失阅读面积时，再试「工具栏独立内缩」。只对能可靠定位顶部边界的窗口启用，并验证弹层锚点；贯穿顶栏的侧栏、自绘标题栏和无法定位的控件沿用完整窗口方案。
