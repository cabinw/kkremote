# 研究范围与证据索引

> 本报告引用的原始证据保留在本地分析工作区，不随仓库提供。文件路径用于定位本地材料，详见 [研究资料说明](../../research/README.md)。

本轮完成本机交付物的第一轮静态分析与 KKRemote 方案设计。没有实现 KKRemote，没有建立远程会话或执行触控/带宽/画质对照测试。目标应用原本正在运行，不表示本轮已观察其连接行为；静态工具加载二进制也不等于运行应用。

后续设计状态：用户已选择A并要求窗口优先、Tailscale/Ponte、高码率低延迟。现行设计见[窗口优先架构](../design/窗口优先架构.md)，多主机工作区仅预留。本文件的二进制研究范围保持不变。

v0.3补充：经用户要求重新比较，设计建议改为原生libwebrtc优先验证、QUIC备选，见[传输复核](../design/传输路线复核.md)。这是结合已有静态证据与上游文档的工程判断，不是新取得的运行时性能结论；本轮未重新逆向、抓包或编写产品代码。

## 工具边界

按用户指定的 REA 技能执行。当前 Codex 会话没有 REA MCP 工具，已用安装的 REA CLI 6.5.0 继续；read-only doctor 报告 Codex 注册未对齐，**没有修改注册、技能或系统配置**。`research/platform/rea-doctor.json`

Casement 的 Mach-O、overview 和四个选定函数取得成功 REA Evidence；函数参数用 ARM64 调用指令交叉核对。Jump 的 Mach-O inspection 成功，但 Hopper 首次分析超时，因此 Jump 的关键控制流主要使用 Apple LLVM 反汇编、Objective-C selector stub 映射和字符串交叉引用，不能宣称已取得完整反编译源码。工具失败和未覆盖范围保留在各自报告。

本机 SDK：Xcode 27.2，Swift 6.4.2。SDK 路径及重点头文件摘要见 `research/platform/sdk.json`。它用于查证 API/枚举，不代表未来最低支持系统也具备所有当前 API。

## 证据等级

| 等级 | 能证明什么 | 本轮例子 |
|---|---|---|
| 直接静态证据 | 这份二进制的某条路径如何构造调用/参数 | showsCursor=false；HEVC Main/Main10分支；DTLS+UDP构造；dirty rect解析 |
| 结构/符号线索 | 模块或协议类型存在，供定位后续控制流 | 未完全展开的输入事件、传输优先级和codec名称 |
| 官方文档 | 文档声明的产品/API能力，受版本和条件限制 | Jump色度档位；SCK HDR配置；QUIC datagram接口 |
| 工程推断 | 可由证据解释的一种机制或候选原因 | 1.5×采集后放大可能降低平板文字清晰度 |
| 设计建议 | KKRemote应该选择的实现与验收约束 | 统一surface、resize事务、有界媒体队列 |

每条产品结论优先链接本机证据。官网可能描述更新的客户端或Beta：例如查阅页面出现10.16/10.17能力，本机Jump为10.15系列，不能套用。静态参数设置也不证明VideoToolbox运行时接受了该参数。

## 原始问题覆盖情况

| 问题 | 覆盖 | 剩余未知 |
|---|---|---|
| Casement如何管理窗口 | 核心路径已回答：CG/AX注册、父子关系、cell、应用过滤与裁剪、尺寸/输入版本 | 完整分类规则与所有应用兼容性 |
| Casement是否使用虚拟显示器 | 创建与HiDPI设置有直接证据 | 当前会话是否启用；各模式适用条件 |
| Casement为什么画面不清晰 | 发现SDR、scale/码率限制、速度优先、视频与无损settle机制 | 用户实际会话档位、客户端缩放和根因比例 |
| HDR/Retina能力 | 已确认检查路径为8位SDR；HiDPI机制存在 | 当前连接的端到端密度；未覆盖路径的HDR能力 |
| 鼠标为何出现 | 已确认独立光标，检查的视频采集不含光标 | iOS显隐策略、模式切换和客户端bug |
| 触控为何不流畅 | 服务端输入、几何与门控结构部分回答 | 客户端手势仲裁与真实时间线，需实机 |
| Jump如何处理数据流 | 采集、dirty rect、16×16活动图、编码、JRTC、节流和反馈边界已回答 | 完整Fluid协议、控制算法阈值、包级恢复及当前路径 |
| Jump高画质来自哪里 | 多编码路径、Main10、色彩/光标分离和官方档位有依据 | 用户当前选择、4:4:4实现细节、HDR实际显示表现 |
| KKRemote如何整合两模式 | 已给出surface契约、媒体/输入/窗口架构与验证阶段 | 选择路线后做技术验证，不应直接视为可交付实现 |
| 下一步如何执行 | A已选定，已细化窗口优先架构、覆盖网接入及阶段验收 | 保持方案阶段，未开始实现 |
