# 通信方案 v1 运行与复测

2026-11-14 接入决定：通信 v1 收敛，主动测试及偶发事件专项排查按用户要求暂停，真机由 iOS 研发使用。普通 Host 保持原配置；以下测试方法和失败证据留档，不是当前继续测试的安排。当前操作入口见[真实体验交接](iOS真实体验接入交接.md)。

这是当前 Lab 的通信配置与复现入口，架构见[通信方案](通信方案-v1.md)，结论见[验收记录](../testing/通信方案v1验收.md)。不含新的客户端布局或 Host 输入执行。

## 基线与生命周期

使用同一提交状态、同一 Release 二进制进行比较。跨 Mac 脚本会核对可执行文件 SHA-256。Xcode 工程和 DerivedData 使用独立目录，测试期间不覆盖正在运行的二进制。2026-11-14 iPhone 已经 USB 安装 Build 12，并完成蜂窝 Ponte 10 分钟复测；见[构建 12 报告](../testing/iPhone蜂窝Ponte构建12复测.md)。此前 Build 10 结果保留原版本口径；TestFlight 没有自动上传。

推荐候选配置：2560×1440 / 60 fps / 20 Mbps 预算；支持时 HEVC Main10 PQ，否则 H.264 SDR；固定 UDP v2、socket、interactive、realtime、HEVC 周期关键帧 10 秒。参数见[配置快照](transport-v1-profile.json)，推荐资格受验收记录中的失败和待验项限制。保留 adaptive 和 Network.framework 作为显式重新建会话的回退选项，不在会话中混用字段试验或 wire version。

其中 pacing / playout 是进程级 field trial：修改它们要重启 Host 并重新连接，单纯重连同一个进程无效。脚本每轮启动独立进程，因此 A/B 参数确实分别生效。这里的回退是明确操作流程，尚未实现运行时自动切换。

手机沿用已有连接偏好和安全存储中的配对码，测试工具不覆盖它们。配对文件只作为路径传参，不把内容放入 shell 历史、argv 或公开报告。Host 与 Viewer 的 playout 字段分别描述各自发送策略；评价手机接收的 RTP hint 时以 Host 配置为准。

Host 持续监听用于接受下一次显式连接，每个媒体 epoch 独立报告。停止观看、切换窗口、App 后台、断开媒体分别记录，不能拼接累计计数制造“持续 60 fps”。原网络地址、端口和用户固定配对码本轮不改变。

## 可复现测试入口

本机已确认 UU Remote 会在自己的捕获生命周期内提交系统显示模式，三次停止捕获后约 28 秒又恢复原模式；Jump 虚拟屏也可能随连接关闭被移除。正式长测先排除这些模式切换，等待恢复完成后再核对固定显示条件，不能只依靠“无人手动改设置”。调用方证据和只读日志查询见[显示模式自动变化排查](../testing/显示模式自动变化排查.md)。不要在测试中循环强制设置 60 Hz 来与其他工具争用显示器。

先新建一个仅放测试素材的独立浏览器窗口，再打开本地 `high-load.html?mode=diagram&speed=3&panels=4&immersive=1`，从 `--list-windows` 明确选择该窗口，不捕获其他用户窗口。服务和素材准备参照 [Fixture 说明](../../Tests/Fixtures/window-capture/README.md)。严格静态用 `mode=static&strict=1&immersive=1`，混合持续负载用 `mode=cycle&phaseSeconds=100&speed=3&panels=4&immersive=1`，每 100 秒图纸 → 滚动 → 原生 60 fps 视频循环。

- `scripts/benchmark-transport-suite.py`：顺序回环、trace 开关与六类故障；保存成功和失败报告，默认每轮 40 秒，不修改全局网络。
- `scripts/benchmark-remote.py`：通过既有 SSH 在 15mac 启动匹配 Viewer；LAN native ICE 与 sgponte 固定 UDP 分别执行，持续 900 秒；`--live-host` 写入有界实时摘要，结束后读取完整的第一媒体会话，不能拿最后五条样本代替长测。短码不经 SSH 命令参数传递。
- `scripts/prepare-phone-transport-run.py`：启动私有 Host 测试进程，USB 启动 iPhone 诊断运行；在手机点击连接，计时结束自动停止并导出。只终止状态文件中仍与程序路径 / 测试目录匹配的旧 PID。
- `scripts/analyze-transport-run.py`：以计数差计算稳态 fps、实际码率；资源、队列与首末 5 分钟比较。缺失指标保留 null，计数重置不产生负吞吐。
- `scripts/evaluate-transport-trial.py`：检查名义时长、两端 ≥59.5 fps、1440p、单一媒体代次 / 编码、全会话零 SDK 冻结与丢帧、有界桥接和源守护覆盖；失败退出码为 1。它不认证光学延迟、画质或持续满 20 Mbps。
- `scripts/analyze-frame-trace.py` / `analyze-rtp-trace.py` / `analyze-receiver-trace.py`：分别分析发送、RTP 关联和接收端阶段；物理呈现继续标未知。

先用 `scripts/build-capture-probes.py --signed-app PATH_TO_KKRemoteLabMac.app` 构建并复用已有开发签名。长测传 `--expected-window-title 'KKRemote Repeatable Load Fixture' --identity-probe .build/CaptureIdentityProbe.app/Contents/MacOS/KKRemoteLabMac`。`capture-source-guard.py` 使用常驻 CoreGraphics 元数据探针，每 10 秒核对窗口 ID、应用名、标题及尺寸；变化或读取失败就停止该测试 Host，报告不得用于验收。不要在性能长测中省略 `--identity-probe` 而使用重复启动 ScreenCaptureKit 查询的旧模式，该模式本身可能扰动捕获。守护进程不保留其他窗口标题，不能检测两次采样之间的短暂变化，因此仍需独立窗口和开始 / 结束画面核对。脚本的 `source-guard.json` 应覆盖整个媒体测试区间；中断 guard、窗口变化或提前结束都要记录为无效，不只保留稳定片段。

最新版探针还通过 [CGGetDisplaysWithRect](https://developer.apple.com/documentation/coregraphics/cggetdisplayswithrect(_:_:_:_:)) 记录与源窗口相交的显示器 ID、逻辑 / 像素尺寸及 [CGDisplayMode.refreshRate](https://developer.apple.com/documentation/coregraphics/cgdisplaymode/refreshrate)。只读，不设置显示模式。模式变化、查询失败或已存在的显示元数据消失都会停止该轮。这里的标称刷新率不表示 ProMotion 每个时刻的实际刷新节奏，0 表示未知，也不证明 HDR / EDR 状态。此前完成的长测只使用旧版窗口身份守护，不追补不存在的显示采样；新守护只能提高后续复测的条件一致性。

本机实测 Device Hub 投屏预览可使原始 SCStream 从约 60 降到约 31 fps；打开 / 关闭复核已记录。性能长测先操作手机连接，再关闭 Mac 的投屏预览窗口，手机 App 保持前台，用 USB 复制报告；不把投屏预览的 fps 当作手机实际接收 fps。系统捕获异常时使用 `Tests/CaptureCadenceProbe.swift` 绕过编码和网络，参数依次为窗口 ID、秒数、queueDepth、minimumFrameInterval 的倒数（0 为不限），只输出计数和时序，不保存图像。苹果对 minimumFrameInterval 的[官方说明](https://developer.apple.com/documentation/ScreenCaptureKit/SCStreamConfiguration/minimumFrameInterval)明确 0 表示系统支持的最高帧率，并非保证 60 fps。

诊断手机参数仅在显式 `--media-diagnostics-run RUN_ID` 下生效，`--media-diagnostics-seconds` 允许 30–3600 秒。帧 trace 需要 `--media-frame-trace`；正式运行不带这些参数。报告位于手机应用 Documents/TransportDiagnostics/RUN_ID，经开发工具的 appDataContainer copy 读取，先创建本机目标目录，再确认 viewer.json 和 trace 均已生成。目录存在不代表计时已经结束。

双 Mac 复测示例（替换已部署 App 路径、源窗口号和本机 LAN 地址；不改现有手机端口）：

```bash
python3 scripts/benchmark-remote.py \
  --ssh 15mac --remote-app /absolute/remote/KKRemoteLabMac.app \
  --sender-app /absolute/local/KKRemoteLabMac.app \
  --host HOST_LAN_ADDRESS --network LAN --route direct-ice \
  --bridge-transport socket --duration 900 \
  --resolution 2560x1440 --fps 60 --mbps 20 --hdr --playout realtime \
  --window-id WINDOW_ID --expected-window-title 'KKRemote Repeatable Load Fixture' \
  --identity-probe .build/CaptureIdentityProbe.app/Contents/MacOS/KKRemoteLabMac \
  --live-host
```

Ponte 对照只把 `--host` 换成已配置的 `.sgponte` 名称，并改为 `--network 'Surge Ponte' --route fixed-udp-v2`；保留同一源码快照、窗口尺寸、显示刷新率与素材参数。原生 ICE 对照与 Ponte 对照同时改变了端点桥接和覆盖网路径，差值不能全部归因于 Surge。

结束后分别对完整 `host.json` / `viewer.json` 执行：

```bash
python3 scripts/analyze-transport-run.py PATH_TO_REPORT.json --output PATH_TO_ANALYSIS.json
python3 scripts/evaluate-transport-trial.py \
  --host HOST_REPORT.json --viewer VIEWER_REPORT.json --guard SOURCE_GUARD.json \
  --seconds 900 --output TRIAL_RESULT.json
```

同时检查 `source-guard.json` 的 `valid`、`monitorCompleted` 和覆盖区间。先核对时长与会话是否完整，再检查全程冻结 / 丢帧和稳态 fps；失败轮次保留，不通过手工裁掉异常片段宣称成功。

验收器还检查身份采样的时间单调且相邻间隔不超过 20.5 秒，防止只有首尾记录的守护假通过；这仍不是连续图像证明。生产等待区上限为 256 包，Network.framework 另有最多 32 个 in-flight，因此该路径的 `pendingPackets` 总上限为 288，socket 路径为 256。

`--capture-depth 3|5|8` 只用于本地因果对照，默认 3；当前完整 3/5/5/3 对照未显示更深队列带来收益。原始捕获探针可在四个位置参数后加 `--hdr` 对照 PQ/P010。不要修改默认后沿用旧二进制的性能结果。

如需隔离传输长测，可明确使用 `--pattern desktop` 并省略窗口号和身份守护。其结果只验证生成源到接收端，不使用真实窗口验收器伪造 `source-guard`，也不能替代真实窗口、HDR 母版或高负载热稳定性测试。

USB 启动被 Locked / 断连拒绝时，该轮属于准备失败。工具会终止刚创建的测试 Host / 守护并保存 `PREPARATION_FAILED.json`，不修改原短码、不重复尝试解锁、不计入媒体结果。用户回到手机旁解锁后用新 run 名启动完整轮次，不拼接之前短测。

900 / 1800 秒是从启动连接计时的名义时长，自动检查最多允许开始出帧前的 5 秒差额，报告仍给出实际媒体观察时间。资源趋势和队列 age 仍需单独审阅，单一布尔值不能替代完整验收。

## 能力协商与兼容

信令会话与媒体 epoch 分离。支持窗口协议 v1 的客户端可查询目录、选择 / 停止观看；旧版没有窗口协议时保留固定媒体源。目录句柄只在当前会话 / 目录有效，最多 128 项，Host 重新核对窗口号和进程 ID。目录标题只在已认证通道传给用户界面，不进性能报告。

Main10 必须同时满足本地硬件能力、SDP 支持以及接收端显式 `hevc-main10-pq` 回答；不满足时使用 H.264 SDR，报告实际 codec 和像素附件。H.264 High 5.1 只在本地硬件编码会话探测成功后广告，不通过修改 SDP 假装设备支持。

固定 UDP v2 与旧 v1 是不同的封装；连接前两端选定匹配版本。v2 外层每个报文上限 1280 字节，全尺寸认证探测用于验证当前端点可达，不代表往后永无丢包或已验证所有路径 MTU。

## 故障与回退

| 现象 | 先查看 | 处理原则 |
|---|---|---|
| 无法配对 | TLS / 端口 / 主机可达性 / 原配对文件 | 不修改用户短码，不取消 TLS 校验 |
| 信令可达、媒体未认证 | UDP 全尺寸探测、桥接错误、原协议版本 | 不自动改成 TCP 视频或公网中继 |
| 到达持续、解码暂停 | NACK / PLI、参考链、VT 失败原因 | 保留恢复机制；不能仅增大 UI 缓冲 |
| 解码正常、显示落后 | observer pending / replacement / backpressure / 主队列等待 | 保持单待提交帧和 epoch 隔离 |
| 发送端先降帧 | capture cadence、source→encode、目标 / 实际码率 | 区分源、FrameDropper、编码与网络，不称作接收丢帧 |
| 带宽不足 | 拥塞预算、实际 payload、生产队列 age | 允许有界降码率 / 降帧；需要时明确改较低档位 |
| 高温或长时退化 | 两端热状态、CPU、footprint、codec | 不隐式降分辨率宣称原档通过 |

资源采样只覆盖当前 App 进程，CPU 的 100% 表示一个核心；不含 WindowServer、Surge、素材浏览器和测试辅助进程。本轮记录 CPU、RSS、physical footprint 与系统 thermalState，不提供 GPU 利用率、瓦数或摄氏温度。统计历史在容量内增长应与泄漏区分，报告导出峰值也不等同于稳定串流峰值。

手机通过 USB 接入开发机，属于 USB 供电条件下的测试；这组 CPU / 热状态数据不能推出脱离 USB 后的电池续航。Mac 的 CLI Viewer 提供接收 / 解码回调统计，不能将其与 iPhone 实际显示视图的提交统计混为同一指标。

媒体队列有界；不因排查在包回调中写磁盘、导出图像或记录媒体内容。统计历史最多 3600 个样本，逐帧 32768 个事件、RTP 4096 个帧分组，覆盖数量可见。资源增长需要区分这些历史填充、系统缓存和持续泄漏；一次 30 分钟平稳也不能证明永不泄漏。

## 版本与验证边界

固定 libwebrtc 版本后再解释 field trial；升级 SDK、改 codec、窗口捕获方式、封装大小、pacing 或显示路径都应重新执行相关对照。诊断故障模式只能由本地 CLI 打开，不通过配对信令开放远程注入。

本轮不改 Tailscale / Surge 的全局设置，不引入公网发现和 TURN。物理端到端延迟、独立 iPad 验收、IPv6-only、输入 / resize / 音频 / 多窗口仍按各自任务处理；文档里的接入契约不等于这些产品能力已经实现。


## 逐帧冻结现场与长测内存对照

新增 `--sample-journal` 用于独立 CLI 会话：逐秒完整样本写入私有 JSONL，异步队列最多 8 条；任何丢记录、写失败、未关闭或序号断裂都不能用于验收。它不能与 `--persistent-host` 混用。`--report-history-limit 60|300|3600` 只改变进程内历史容量，缩短容量必须同时写 journal，正常默认仍为 3600。`benchmark-remote.py` 保存原始 `.retained.json`，校验 journal 的完整顺序、媒体计数连续和最终尾段一致后，重建用于验收的完整报告。不能仅分析最后 300 秒来声称长测成功。

显式开启 `--frame-trace` 时，接收端在 SDK freeze 计数首次增加后保留一份有界现场，并通过已认证数据通道通知发送端保留对应现场。每个媒体代次最多一份，不开启对方的诊断，也不在媒体回调中写盘。正常 trace 环仍滚动；结束后输出 `incidents/*-first-freeze.json`。因现场快照有额外内存占用，内存容量 A/B 必须关闭 trace。

socket + trace 分支增加 Darwin `SO_TIMESTAMP_MONOTONIC` / `recvmsg`：内核值经 `mach_timebase_info` 转成 uptime 纳秒，缺失 / 无效值保持未知。它是 IP 栈交付时间，不代表网卡或 Ponte 外层到包时间。普通 socket 路径仍使用原 `recvfrom`，Network.framework 路径没有该观测点。实现依据为 Apple [XNU ip_savecontrol](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/netinet/ip_input.c)；本机单测通过故意阻塞接收队列 150 ms 确认内核时间与应用回调时间能分开。

用 `scripts/analyze-freeze-incident.py --sender SENDER_INCIDENT --receiver RECEIVER_INCIDENT --output RESULT` 对齐同一 SSRC / RTP 时间戳的相邻帧。只比较各自主机上的间隔，不相减两台设备的绝对时钟；包序号元数据不完整就不声称完整匹配。`analyze-receiver-trace.py` 同时覆盖 Mac CLI 的 SDK renderer 回调；它仍不代表物理屏幕呈现。

CLI 收到 SIGTERM 后通过主运行循环正常停止、关闭 journal 并导出 trace，返回失败；显示 / 窗口身份变化的轮次仍由 guard 判为无效。保留诊断不等于可把被中断轮次算作完整验收。
