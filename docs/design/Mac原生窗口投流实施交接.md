# Mac 原生窗口投流：实施交接

更新：2026-11-17。状态：**设计与源码核查完成，以下 DW0–DW6 均待实施**。面向接手 Mac 客户端的研发 agent；本次没有修改程序、安装客户端、重启 Host 或进行真机测试。源码基线为 `1f353da`，媒体与窗口代码继承自 `38da1fb`；落地前核对后续接口变化。

**目标：电脑 A 上用真正的 macOS 窗口呈现电脑 B 的应用内容。窗口移动、大小、层级、最小化、全屏与关闭由 A 管理；B 只负责运行应用、捕获内容和执行明确的远端输入。客户端不得自动改变 B 的窗口位置或尺寸。**

首个完整场景：在 A 选择 B 的 Codex 窗口，打开本地独立窗口，流畅拖动、调整本地视口、输入文字和滚动；关闭本地窗口后，B 的 Codex 和正在运行的任务继续存在。随后验证 Chrome 和 Excel。网络使用现有 Ponte / LAN，HDR、60 fps、1440p 面积和 20 Mbps 预算保持不变。

## 1. 必须保持的边界

- 使用物理窗口捕获；不创建虚拟屏，不调整任一端的系统分辨率、刷新率、Dock 或显示器排列。
- 本地窗口的位置和大小只存客户端。不得把 `NSWindow` 的移动、缩放、最大化、全屏、恢复事件转换为远端 AXPosition / AXSize / 最小化操作，也不得在缩放结束后悄悄发送 resize。
- 连接、选窗、被动观看、本地窗口获得焦点和拖动外壳，都不自动激活或置前远端应用。
- 实际键鼠输入可能需要激活远端应用。当前 Host 使用同一个 macOS 登录会话，不能承诺与 B 的本地用户同时独立操作不同应用。观看与控制分开，控制期间明确显示状态，遇到远端本地操作冲突时暂停控制。
- 沿用本地私有配置中的地址、端口和配对信息；文档、默认示例、提交中不包含这些值。未来连接能力见[原生连接交接](原生连接与自有STUN实施交接.md)，Mac 窗口客户端不等待 CloudKit / 自有 STUN 开发完成。
- 不接管 iOS 交互，不修改 `overlay-test/`、`ui-gemini/`。偶发冻结专项、整屏模式、文件传输、多主机正式交付不作为本阶段前置任务。

**“像原生应用”有两个实际限制。** 窗口外壳、系统动画、光标和输入法可以本地化，远端应用内容仍有网络与编解码延迟；所有本地呈现窗口首先属于 KKRemote，一个远端应用不会自动成为独立的 Dock / Cmd-Tab 应用。首版提供原生窗口、Window 菜单与窗口切换，不伪装已实现独立应用身份。

## 3. 推荐架构与备选

采用 **AppKit 管窗口和高频输入，SwiftUI 管设备列表/设置，已有媒体呈现器管视频**。Apple 的 `NSWindow` 提供本地窗口、全屏、子窗口和窗口恢复等系统接口，适合作为外壳基础。[Apple NSWindow](https://developer.apple.com/documentation/appkit/nswindow)

| 方案 | 适用情况 | 决策 |
|---|---|---|
| AppKit NSWindow / NSWindowController + NSView 视频层 | 独立窗口、responder、精细输入、live resize 与跨显示器控制 | 主方案 |
| SwiftUI WindowGroup + AppKit 桥接 | 设置页、窗口目录、简单产品 UI | 可用于外层；视频帧不通过 SwiftUI 状态逐帧刷新 |
| 单个大画布中绘制很多假窗口 | 跨平台工作台、统一画布 | 当前不采用；不能直接满足本地系统窗口管理目标 |
| 专用 Metal 呈现器替换现有 layer | 后续确实需要复杂裁切、合成或可测量的性能收益 | 有证据再做；首版不重写已经接通的 Main10 路径 |

建议新增 `Apps/MacClient/` 与独立客户端 target（**建议路径，当前不存在**）。先以薄适配器复用 Lab 的会话与媒体，逐步提取公共核心；不要复制整个 TransportLab 后维护第二份编解码/桥接代码，也不要把新客户端写进 iOS 的共享页面。

初始系统范围沿用 [project.yml](../../project.yml) 的 macOS 15+，先验 Apple silicon。Viewer 使用普通 AppKit 事件接收，不因观看远端窗口就在 A 请求屏幕录制或全局辅助功能权限；需要采集/注入权限的是 B 的 Host 角色。Host/Viewer 可以将来同包分角色，权限、设置与生命周期仍分开。Intel、应用沙盒分发与独立 Host 产品安装流程另行验收，不默认已支持。

| 拟定模块 | 职责 | 所有权边界 |
|---|---|---|
| MacWorkspaceCoordinator | 本地窗口集合、位置恢复、当前输入目标、客户端总资源预算 | 只拥有 A 的窗口状态 |
| RemoteWindowController | 一个主 surface 对应一个 NSWindow；标题栏、状态、菜单、关闭订阅 | 不写 B 的窗口几何 |
| RemoteContentView | 视频视图、显示变换、命中检测、键鼠和 NSTextInputClient | 发内容输入，不发本地窗口管理事件 |
| WindowSessionAdapter | 目录、订阅、媒体代次、错误与诊断，隔离 LabModel 细节 | 通过已认证会话绑定 Host，不能根据 UI 标题决定目标 |
| HostSessionPool（DW6） | 每台 Host 的共享会话、多 surface 路由、租约和总预算 | 多窗口/多主机预留；首版只有一个活动订阅 |
| 既有通信核心 | ScreenCaptureKit、VideoToolbox、libwebrtc、Ponte、信令、遥测 | 保持单一实现，跨客户端接口变更先记录契约 |

媒体接收、解码、统计聚合不等待 AppKit 主线程；主线程只处理短小的界面操作和必要的 layer 提交。沿用“最新帧替换旧待呈现帧”的有界策略。验证 AppKit 拖窗、菜单 tracking、live resize 时不会阻塞媒体处理；若要改变调度方式，根据测量实施，不能仅换一个 timer 宣称解决。

## 4. 本地窗口行为契约

| 用户在 A 的操作 | A 的行为 | 对 B 的影响 |
|---|---|---|
| 拖本地标题栏、吸附、系统平铺、调整层级 | AppKit 即时完成，保存 localFrame | 无移动、resize、焦点或输入消息 |
| 拉本地边缘改变大小 | 更新视口；默认等比完整显示，可切原像素局部查看 | 不改变源窗口，不重排应用 |
| 本地绿灯、全屏、切 Spaces | 仅改变本地外壳与 viewport | 无源最大化/全屏操作 |
| 本地黄灯、隐藏 KKRemote | 本地最小化/隐藏；可暂停或降低该订阅视频负载 | 不最小化/隐藏源应用 |
| 本地红灯、Cmd-W | 关闭本地呈现并取消该订阅；共享连接是否保留由其他订阅决定 | 不关闭源窗口或终止源任务 |
| Cmd-Q | 退出本地客户端，释放输入和订阅 | 不退出 B 的应用 |
| 本地窗口变为 key window | 改变本地输入路由，先释放上一目标的持有输入 | 不立即激活/置前 B |
| 点击内容、在已选择的远端内容区输入 | 获得控制租约并确认实际目标后转发；失效就拒绝 | 可能激活 B 的目标应用，这是实际远端控制 |
| 本地放大、平移、切换“适合窗口/原像素” | 更新本地显示变换及命中检测 | 无布局请求；纯平移不应重建媒体 |
| 断开与重连 | 保留本地窗口框和视口偏好，重新验证目标 | 不恢复、不移动、不调整 B 的窗口 |

窗口大小恢复使用客户端独立身份，不依赖 Host 的瞬时系统窗口号。恢复到已拔掉的本地显示器时，只把 A 的外壳放回 A 的可见区域；不得借此改变 B 的显示设置。

本地窗口管理在网络停顿时仍能完成。动态内容停顿必须标记“重连中/画面已暂停”；不要用平移旧画面或延迟隐藏状态假装远端内容已响应。离开内容区/切换目标时，允许发送释放既有按键、取消手势、归还租约及订阅状态消息；这些是清理消息，不能顺带激活应用、创建新输入或修改源布局。

## 5. 清晰度、字号、几何与 HDR

### 5.1 不改源窗口时能做到什么

源窗口像素足够时，保留真实采样密度、减少中间重采样、让本地呈现对齐 backing 像素。源只有 860×1746 时，放大不能变成真实的 1290×2618 细节。高码率与锐化也不能补回没有捕获的字形。Mac Retina 的匹配通常比强行铺满手机更容易，但不能因此保证任意窗口原生清晰。

1440p 预算定义为每个活动主画面不超过 **3,686,400 编码像素**，允许横屏或竖屏。先去除无用阴影/填充，再保持纵横比选择编码尺寸，计入编码对齐后的实际面积；不得超过预算后仍称“1440p 档”。例如 2880×1800 源像素超出此预算，必须说明降采样，或者用户主动选择局部查看/采集策略；不能悄悄改源窗口来凑预算。

两种本地显示方式：默认“适合窗口”保持内容完整，接受必要缩放；“原像素”让一个编码内容像素对应一个本地 backing 像素，超出部分本地平移查看。如果源已降采样，UI 应称“编码像素 1:1”，不能称“源端原生”。任意大小外壳、完整画面、严格 1:1 三者不能总是同时满足。

字号随远端应用内容而来。缩放本地视口可改变观看大小，不会引发远端排版；客户端不自动发送应用缩放快捷键。用户明确在远端应用里调整字号属于内容操作，另行呈现，不与本地窗口尺寸绑定。

Apple 建议使用 backing 坐标转换而非单凭 `backingScaleFactor` 计算绘制；系统缩放模式下 backing 像素也不必然等同面板物理像素。验收记录屏幕模式和实测内容矩形，不能只看到倍率 2 就宣称物理像素精确。[Apple backingScaleFactor](https://developer.apple.com/documentation/appkit/nswindow/backingscalefactor)

### 5.2 坐标和版本

维护四套明确坐标：B 的窗口逻辑点、采集内容像素、编码帧像素（含裁切/填充）、A 的内容视图点与 backing 像素。通过一份可逆变换做呈现和点击反算，统一处理左上/左下原点差异、裁切、黑边和缩放，不分散写比例公式。

本地 `presentationRevision` 与远端 `layoutRevision` 分开。本地拖动窗口不改变远端 revision；B 用户手动移动/resize、源屏倍率变化、捕获裁切变化会产生新的远端几何。只在与新几何匹配的首帧呈现后启用对应输入，旧布局点击拒绝；已持有按键/按钮的释放走独立清理路径，不能因 revision 过期被丢掉。

接口至少携带 `sourcePointRect`、`capturePixelRect`、`encodedExtent`、`contentPixelRect`、`interactiveRegion`、`streamEpoch`、`layoutRevision` 和帧关联信息；已有[核心契约](contracts.md)为设计起点，不把这些全当作现有 wire 字段。纯 UI 拖动不上传屏幕位置；可见性、解码能力和期望采样密度是质量建议，Host 无权把它解释为 resize。

### 5.3 HDR 与跨屏

复用 ScreenCaptureKit → 10 位像素 → HEVC Main10 → RTP/Ponte → VideoToolbox → 色彩管理呈现。传递真实 primaries/transfer/matrix/range，源内容为 SDR 时不得仅凭 10 位容器标记“真实 HDR”。Apple 的 canonical HDR capture 面向其他 HDR 设备分享，不应随本地外壳拖动重新改 Host 显示模式。[Apple HDR 捕获说明](https://developer.apple.com/videos/play/wwdc2024/10088/)

A 窗口跨 HDR / SDR 显示器时更新呈现能力和转换；确保没有重复 tone map，文本和系统窗口装饰保持正常。先复用现有 `AVSampleBufferDisplayLayer`，验证 SDR 回退、EDR 余量变化和窗口跨屏后再决定是否需要自定义 Metal。不要照搬只在 iOS 分支中的显示设置并假设 macOS 已验收。

源变化目标 60 fps、视频预算 20 Mbps；静态窗口不填充重复帧凑数。本地系统窗口动画可以跟随客户端显示器节拍，但这不代表远端视频已变成 120 fps。遥测分别记录采集、编码、接收、解码、提交与实际可观测呈现；enqueue 不是屏幕显示时间，RTT 不是输入到画面延迟。

## 6. 标题栏、光标与应用内界面

采用本地系统交通灯、边框与阴影，连接来源放在轻量标题/状态区。源阴影不重复编码，避免“窗口套窗口”。但 Codex、Chrome 等应用可能把标签、工具条、拖动区混在同一顶部区域，不能固定裁掉顶部若干像素。

| 情况 | 呈现与输入策略 | 验收要求 |
|---|---|---|
| 已有可靠内容区/窗口按钮元数据的应用 | 裁去确认的装饰；必要的标签与工具条保留；更新点击变换 | 交通灯只有一套可操作，本地拖动不触发 B |
| 自定义标题栏、归属区域不确定 | 保留完整内容与薄本地外壳，显式标记保守模式；未知顶部区域先只读或通过已验证规则开放 | 不为美观裁掉应用按钮，不把源系统按钮当本地按钮 |
| 显示了源交通灯/拖动区 | 通过已验证命中区域屏蔽源窗口管理动作；无法识别时不提供该区域交互 | 不出现点击源绿灯改变 B 布局的隐含路径 |
| 窗口圆角、HDR 内容边缘 | 由本地外壳裁剪，内容矩形独立于阴影 | 不把透明边缘烘焙成粗黑边，也不裁掉有效内容 |

仅从视频像素无法可靠识别任意应用的系统装饰。DW4 的首批可交互应用需要明确验证过的命中区域；未知应用可以先只读，不能以泛化点击绕过“不改变源布局”的边界。首版不重绘 Codex/浏览器的应用内部工具栏。

光标位置由 A 的系统光标立即显示，采集图像不烧入 B 的鼠标。光标形状/热点可作为独立元数据按能力协商；通用远端形状获取尚未保证，先用本地箭头和已知区域的 I-beam，并明确降级。只有控制状态下的内容 hover 才发往 B，不为本地光标移动等待视频帧。

## 7. 输入、焦点与菜单

### 7.1 键鼠和输入法

- 只在 RemoteContentView 是输入目标且租约有效时发送内容事件。AppKit 标题栏、边框、设置页和本地状态控件不经过远端输入管线。
- 补齐鼠标 down/move/drag/up、双击、右键、修饰键、精细滚动与 phase/momentum；当前点击型接口不等于完整拖拽。移动/连续滚动可以有界合并，按钮和按键边沿必须保序；溢出或超时就取消手势并释放，不能无限积压。
- Cmd-Tab、Mission Control、Cmd-反引号、Cmd-M、Cmd-W、Cmd-Q、Cmd-H、Control-Cmd-F 保留本地系统/窗口语义；Esc 优先取消本地输入法/浮层，再按明确规则处理本地全屏或远端取消。内容焦点下的 Cmd-S、查找、编辑等应用快捷键发远端；需要远端关闭/退出的操作只能通过名称明确的额外命令，首版可不提供。写出完整优先级表并覆盖菜单 keyEquivalent，避免一键双发。
- `NSTextInputClient` 在 A 维护 marked text 和候选界面，提交确定文本后发送 B；物理键事件用于快捷键、终端控制等场景。一个文字输入不能同时发送字符文本和可打印 key-down。[Apple NSTextInputClient](https://developer.apple.com/documentation/appkit/nstextinputclient)
- 有可靠远端 caret/selection 元数据时把候选框锚定在本地映射位置；没有时使用明确的本地输入浮层，不能伪造远端完整文本模型。处理中文拼音、组合字符、emoji、退格、取消候选和焦点切换。
- 失焦、切换 surface、关闭窗口、租约撤销、网络断开都释放已持有按键/鼠标；Host 也设置租约到期清理，不能只依赖客户端成功发出 release。

本地输入法可先显示组合文字，但远端提交回执不等于应用已经绘制，不能乐观重画整段远端文档。滚动先保证事件与队列正确，不用移动旧整帧冒充远端滚动；固定工具栏与弹层会让这种预测产生明显错误。

### 7.2 远端焦点与本地用户冲突

一个 Host 同一登录会话内同一时刻只有一个有效控制目标。客户端获得 key window 仅选择候选目标；首次实际内容操作才申请/切换控制。当前 Host 的 focus 会激活/置前应用，必须在状态中可见；不得因统计、目录刷新、窗口拖动、重连首帧而触发。

B 本地用户切换焦点或操作其他窗口时，优先本地用户，暂停远端输入并释放持有状态，等待用户明确继续。检测不能靠轮询标题猜测，要将焦点观察、注入事件来源及租约状态一起验证。无法保证后台注入的应用就声明需要置前；不连续强抢焦点，不在每次点击后自动“恢复”另一应用焦点。

### 7.3 菜单、sheet、popover 与模态

单独捕获一个窗口不等于捕获整个应用。Apple 提供指定窗口的 filter 和 `includeChildWindows` 配置，但不能据此保证所有 desktop-independent 路径都包含任意菜单；本机 SDK 对后者的说明还涉及 display-bound window/application sharing。以实测矩阵决定支持范围。[单窗口 filter](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init%28desktopindependentwindow%3A%29)、[includeChildWindows](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/includechildwindows)

窗口族协议预留 `parentSurfaceID`、角色、anchor、z-order、modal 状态与授权范围。捕获已经包含的弹层不重复叠加；独立弹层通过关联 surface 或受控合成显示。关联界面在 A 跟随本地主窗口移动，B 的真实窗口不动。主窗口进入模态时只允许正确的对话框目标收输入。

同一 PID 不是充分授权依据；不要为了显示菜单订阅该应用全部窗口或整屏。无法确定归属时提示选择/不支持。普通 HEVC 4:2:0 帧不自带弹层透明度，主机合成、遮罩或不透明 surface 必须明确选择并验证 HDR 混合。

B 的全局菜单栏不在单窗口图像内。先支持应用快捷键与已捕获的上下文菜单；后续可评估基于可访问性语义的明确菜单命令。不得把静态复制一套“文件/编辑”菜单当成通用远端菜单同步，也不得静默改成整屏捕获。

## 8. 生命周期、恢复与资源

建议客户端状态：发现 → 订阅中 → 可观看 → 可控制 / 只读 → 暂停 / 重连 → 源已关闭 / 已取消订阅。用户可随时关闭本地外壳，无需等待网络响应。暂停时显示最后有效帧的状态；退出、解绑时及时释放 track、layer、解码缓存和统计订阅。

源窗口关闭、应用退出、权限撤回、最小化、隐藏或屏幕锁定分别反馈；捕获持续性以真实帧状态为准。不通过自动取消最小化、搬到可见区域或重建虚拟屏来“恢复”画面。B 用户手动改变窗口尺寸时重新协商内容几何，不反向修改 A 的外壳；当前 Host 可能要求重新选择，产品化需要 DW3 改进。

身份使用 `hostID + sessionID + surfaceID + generation`，媒体另有 `streamEpoch`。进程号、CGWindowID 会重用，目录标题会改变；同一标题、同一系统号或旧 UUID 都不足以自动重绑。客户端跨重连保留的是本地布局偏好，Host 未能证明是同一授权对象时要求重新选择，禁止向候选新窗口重放旧输入。

关闭 A 不执行 HostWindowLayout 的恢复操作；本轮根本不取得任何源布局租约。若旧实验留有恢复记录，应由对应实验流程独立处理，不混入新客户端的 detach/disconnect。

DW1–DW5 先一个活动主窗口。DW6 再增加同 Host 多窗口：一条受管会话或明确的会话池，多 track/surface 映射，共享主机带宽与硬件编码资源。**20 Mbps 是本轮总视频预算，不是每开一个窗口就再加 20 Mbps**；活动窗口优先，后台/遮挡窗口降帧或暂停。RTCP、重传、隧道开销单独统计，链路实际字节数可高于视频预算。

多 Host 将来使用各自会话、身份、租约和故障域，在 A 放若干独立 NSWindow 即可；无需先创建一个虚拟显示器或整屏流。再加客户端总带宽/解码/内存预算，不能让多台 Host 各自无上限发送。当前单 viewer 限制没有解除前，不宣称 Mac 与 iPhone 可同时连接同一 Host。

## 9. 协议增量与兼容方式

下表为拟定能力，不是当前实现声明。通过握手能力协商逐项启用；不识别的能力默认关闭，旧 iOS 行为保持可用。

| 能力/字段建议 | 用途 | 不允许的解释 |
|---|---|---|
| `localPresentationOnly` / `remoteLayoutWritable=false` | 声明本地窗口模式，Host 禁止由视口变化触发布局 | 不能只在 UI 隐藏开关而 Host 仍 resize |
| `surfaceDescriptor` + generation | 可验证的身份、角色、状态和授权边界 | 不以应用标题作为安全身份 |
| `contentGeometry` + layoutRevision + 首帧关联 | 原生内容、编码裁切/填充和输入反算 | 不把客户端窗口 frame 当源 frame |
| `presentationHint` | 可见性、目标采样密度、质量/帧率预算 | 只影响采集/编码策略，不改源应用字号或尺寸 |
| `inputV2` + lease + sequence + expiry | 完整键鼠/文本和陈旧事件处理 | 重连不补发旧点击；文本重试须去重 |
| `cursorMetadata` | 形状、热点、可见性与版本 | 不重放视频里的源指针位置覆盖本地光标 |
| `surfaceFamily` | 已授权关联窗口、模态、父子锚点和独立几何 | 不自动升级到应用全量/整屏权限 |
| `subscriptionPolicy` | pause/resume/detach、按 surface 分配资源 | 暂停传输不等于远端最小化 |

Mac agent 可以先实现与现有接口兼容的只读窗口外壳。身份/几何/输入升级由通信侧负责共享定义与 Host 执行，Mac agent 负责客户端消费和 AppKit 行为。若旧 Host 缺少能力，降级只读/完整 fit，并显示真实原因，不能发送旧 `viewport` 让自动布局替代新接口。

## 11. 验收矩阵与量化方法

下列是**待执行验收**。两台 Mac 优先 LAN 后 Ponte；端点/配对保持既有私有配置。使用自建、明确选定的测试窗口加 Codex/Chrome/Excel，不移动用户其他窗口；不占用 iPhone 或重启正在被其他会话使用的 Host。

| 测试 | 操作与记录 | 通过标准 |
|---|---|---|
| 本地管理隔离 | 对选定源只读记录 AX/CG bounds；A 连续拖动/resize/全屏/最小化/恢复/关闭；记录控制消息与 Host AX 写入 | 客户端造成的源位置/尺寸写入为 0；外壳事件产生的远端焦点/新内容输入为 0，仅允许释放已有输入及订阅清理；源进程和任务继续 |
| 网络独立性 | 在测试会话适配层注入延迟/断流，不改系统全局网络；本地拖窗、开菜单、关闭 | 不等待网络返回；主线程无同步 socket/解码等待；暂停状态正确 |
| 本地响应 | 记录 NSEvent 到本地状态提交、主线程长任务与屏幕录制；60 Hz/高刷分别测 | 初始目标本地事件到状态提交 p95 < 16.7 ms、无由客户端造成的 > 50 ms 阻塞；明确不等于端到端显示延迟 |
| 源/编码/呈现像素 | 文本/单像素线/棋盘格；fit 与 1:1；不同 backing 显示器与源小窗口 | 原像素路径无额外亚像素缩放；必要降采样/系统缩放有说明；不超面积预算 |
| 动态与 HDR | 真实浏览器滚动、视频、灰阶、高光；源能持续提供 60 fps 时测 | 记录源→编码→接收→呈现各级 fps/丢帧；动态接收/提交接近 60，无持续队列增长；高光有层次、灰阶无偏色，不能只报 H265 标签 |
| 几何/生命周期 | B 手动 resize/移动、退出应用、重开同名窗口、断网重连；A 跨屏 | 陈旧点击/帧被拒绝，新几何首帧后才恢复输入；不按同名/旧系统号自动绑定 |
| 输入与焦点 | 中文/emoji/组合输入、快捷键、拖选、精细滚动、按下时失焦/断网；B 本地切应用 | 不双发、不丢释放、不无限积压；本地系统快捷键正常；B 冲突优先本地 |
| 关联界面 | Codex 设置/对话框、Chrome 右键/文件对话框、Excel 菜单与模态 | 能操作的明确验收，不能操作的显示限制；不漏采集授权、不误点遮挡父窗口 |
| 资源释放 | 30 次订阅/关闭及重连循环，随后至少 10 分钟稳态；记录 RSS/GPU、解码器、track、队列 | 每次回到合理空闲基线，资源计数回收，无随循环单调增长；阈值按 DW1 基线登记，不冒称解决所有历史冻结 |
| 多窗口（DW6） | 两个窗口争用带宽、关闭其一、切前后台 | 20 Mbps 总视频预算，后台降载有效，单订阅生命周期独立 |

把“本地外壳顺滑”和“远端应用响应快”分别报告。输入到画面延迟需要输入/应用变化标记及可解释的时钟关联，或外部拍摄；不同机器的单调时钟不能直接相减。当前项目的历史 iPhone 测量不能替代 Mac 桌面客户端验收。
