# iOS 测试界面改版草案

状态：待用户审核。2026-11-13。初版设计完成后，用户追加授权 USB 安装真机测试；已完成本地实现并安装 0.1.0（7）供真机审核。尚未提交 Git 或上传 TestFlight。

## 目标

启动后进入「测试」页，一次点击即可使用当前 Ponte 测试配置连接。视频和接收端关键数据位于第一屏；连接表单移到独立「设置」页。沿用现有媒体链路与 HDR 渲染，不调整 Mac 捕获、编码和配对行为。

## 测试页

- 顶栏：KKRemote Lab、当前会话主机与网络标签、连接状态。网络标签不证明实际外层隧道类型。
- 保持视频原比例，默认完整显示；右下角全屏入口。常规竖屏下，预览、数据和连接按钮在一屏内。
- 视频下方：实际像素尺寸、实际协商编码、从解码像素格式确认的 SDR 或 10 位 PQ；不能根据用户设置或编码名独自推断 HDR。
- 四个主要读数：接收 fps、实际视频 Mbps、控制消息往返 ms、接收抖动缓冲 ms。
- 一行显示本次会话累计冻结、解码丢帧、RTP 丢包；另显示当前屏幕 HDR 余量。
- 底部操作：详细数据、连接 / 取消连接 / 断开连接。无样本显示「—」；连接建立但未收到画面时显示「等待首帧」，不伪装成视频正常。
- 保留简短提示：往返不是画面端到端延迟。20 Mbps 是发送上限，实际码率不应人为补齐。
- 详细数据用 sheet 展示 RTT P95、解码耗时、NACK、重传、帧间隔、首帧耗时、UDP 队列丢弃 / 超时分片、色域 / 传递函数、报告导出。当前端未提供的数据用「—」，不当作 0。
- 全屏时完整显示视频并保留紧凑 fps / Mbps / RTT 浮层；右上角固定退出入口，隐藏控件不拦截点击，不切换视频源。

## 设置页

常用连接：主机地址、配对码、信令端口、媒体端口。配对码默认隐藏，支持显示 / 隐藏。

初装内测默认使用当前已确认的主机与配对码（保持不变）、45990 / 45991、固定 UDP v2、UDP socket、Surge Ponte 标签。用户已有有效配置优先；升级不得覆盖用户修改。具体测试默认值通过忽略的 `Config/Connection.local.xcconfig` 注入内部安装包，敏感值不写入本草案或公开报告。

普通设置通过设备本地持久化，配对码通过 Keychain 保存；校验合法后保存。端口必须在 1–65535，地址和配对码不能为空。输入过程中不立即覆盖有效连接配置。

设置变动在下次连接生效，不打断当前会话；返回首页时仍显示当前活动会话的主机 / 协议。恢复测试默认值只重置连接配置，不停止媒体，也不旋转主机密钥。

将当前 iOS 页面中的「发送端参数」选择器移除：这些参数不会改变远端主机，容易误导测试。分辨率、fps、码率仍在 Mac 配置，手机显示实测结果。本机回环自检与第三方许可放设置下方的「测试工具与许可」，自检须明确不代表远程链路性能。

## 数据映射与状态

| 界面 | 现有数据 | 语义 |
| --- | --- | --- |
| 接收帧率 | `sample.fps` | 解码回调频率，不是测得的屏幕显示频率 |
| 实际视频码率 | `sample.videoMbps` | 视频有效载荷，不含全部隧道开销 |
| 控制消息往返 | `controlRTTMilliseconds` | 控制探测 RTT，不是捕获至显示延迟 |
| 接收缓冲 | `jitterBufferMilliseconds` | 抖动缓冲平均停留时间 |
| 冻结 / 解码丢帧 / 丢包 | `freezeCount` / `framesDropped` / `packetsLost` | 当前会话累计值；需要区分计数未提供与零 |
| HDR 余量 | `displayHeadroom` | 当前屏幕余量；≤1 显示 SDR 亮度范围，缺失则「—」 |
| 实际视频格式 | `width` / `height` / `codec` / `decodedPixelFormat` | 首帧 / 实际统计到达后再展示 |

用户主动断开时不把旧读数保留成实时结果；上一轮数据可通过报告查看。失败 / 中断在首页显示简短原因和重试按钮，详细错误进入诊断。采样停止时显示数据已暂停，避免旧值持续显示为实时数据。

## 适配与实施边界

- 标准 iPhone 竖屏优先（375×812、390×844、430×932 点）；首页无需先滑过设置。
- 紧凑高度减少预览面积和留白，优先保留 fps / Mbps / RTT 与冻结；大字体模式允许必要滚动，避免强制缩小文字或裁切控件。
- iPhone 横屏采用视频与紧凑统计并列；全屏模式隐藏普通表单与底栏。iPad 横屏视频在左、实时统计在右，设置继续为第二页。
- 保持同一个 `LabModel` 和视频 renderer 生命周期。切换 tab / 打开诊断不得触发 stop、重复绑定、重复采样或重建 HDR layer。当前 App 进入后台停止会话的行为暂不改变。
- 首版不改变 Mac UI、媒体协议、颜色转换、捕获、码率、配对码或运行中的服务器。
- 布局预览中的数字和截图用于审核排版；不代表新的实测，也不用于 HDR 亮度验证。预览按钮不会连接真实主机。

## 审核通过后的验证

1. 修改 iOS 布局、配置持久化和必要的状态展示；保留 Mac 分支。
2. 检查小屏 / 横屏 / 深浅色 / 辅助大字体，及初装、升级、有保存配置、无样本、连接失败、断开与重连。
3. 验证设置页来回切换、诊断 sheet 和全屏不打断真实视频、不增加缓冲；每秒更新统计，不把整棵视频视图反复重建。
4. 原 Ponte 参数回归真实 HDR 窗口：1440p、60 fps、20 Mbps 上限；确认 H265 / 10 位 PQ、接收性能及报告字段未退化。
5. 用户审核后再提交代码并更新内部 TestFlight。当前真机为 USB 构建 7，TestFlight 仍为构建 6。
