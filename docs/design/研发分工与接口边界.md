更新：2026-11-14。按用户最新分工，通信层与客户端交互分别推进；本文件替代早期由一个会话顺序完成全部窗口产品的安排。已完成能力和未通过的验收不因重新分工而改变。

## 两条工作线

| 负责人 | 负责范围 | 下一项 |
| --- | --- | --- |
| 「通信协议研发」会话 | Mac / iOS 共用信令、媒体、Ponte、编解码、队列及接入契约 | v1 收敛交付；暂停主动测试与偶发事件排查，按需解决 iOS 接入阻塞和正式控制接口缺口 |
| 「iOS 研发」会话 | 客户端布局、选窗、视口、手势、键盘、生命周期及客户端交付 | 使用真机接入现有 Main10/Ponte，按该会话最新授权推进真实体验；保持正式只读能力与 WPS 本机控制原型的区分 |
| Mac 端功能（尚未指定实现会话） | SCWindow / AX 目标匹配、目标窗口尺寸修改、焦点与输入注入、Mac Host 产品界面，以及 Mac 客户端专属交互 | 作为单独配合项保留，不默认为通信优化或 iOS UI 的职责 |

通信优化不再代做客户端布局或手势，客户端原型也不等待所有压力测试完成。iOS 会话提出的虚拟显示器方案仍属候选设计，本次交接不启动虚拟显示器、整屏或多主机实现。

## 文件边界

- 通信侧主要维护 `PeerEngine.swift`、`SignalTransport.swift`、`WindowSession.swift`、`DatagramBridge.swift`、`MediaDatagram.swift`、`UDPSocket.swift`、`LoopbackDatagramPort.swift`、`WebRTCRuntime.swift`、`HEVCCodec.swift`、`LabH264Factory.swift`、`EncoderTelemetry.swift`、`WindowCaptureSource.swift`、CLI 探针与性能脚本。
- iOS 侧主要维护 `IOSLabView.swift`、`ConnectionPreferences.swift`，接手 `RemoteWindowsView.swift` 的客户端展示和交互。后者为 Mac / iOS 共享视图，修改时保留 Mac 可编译性。
- `LabModel.swift` 是共享接口：通信侧负责连接、窗口事务、媒体代次和统计；iOS 侧通过公开状态与方法使用它。新增 UI 状态优先放客户端模型，必要的接口变化先写明契约和调用方影响，避免同时编辑同一段逻辑。
- `HDRVideoView.swift` 的解码帧提交、色彩与低延迟队列属于媒体呈现核心；视口、缩放、手势与布局由 iOS 侧在外层适配。需要跨这条边界时先记录变更范围。
- `project.yml`、Xcode 工程、共享配置、签名与版本号为共同文件，一轮只由一个会话修改和生成。各自使用独立 DerivedData；不要覆盖正在运行的 Host 二进制。手机安装、Host 重启和性能长测错开进行。
- 保留工作区现有未提交改动；`overlay-test/` 属于其他工作，不在本次交接范围。

## 已有接口与后续契约

构建 8 的客户端通过 `LabModel.connect()` / `stop()` 管理连接，通过 `refreshRemoteWindows()` 获取目录、`selectRemoteWindow(window)` 选择窗口、`selectRemoteWindow(nil)` 停止观看并保留连接。可观察 `windowSupported`、`remoteWindows`、`selectedRemoteWindow`、`windowBusy`、`catalogLoading`、`windowStatus`、`windowError`、`track` 和 `sample`。停止观看与断开连接是不同操作。

| 接口 | 通信侧 | iOS 侧 | Mac 端配合 |
| --- | --- | --- | --- |
| 目录与订阅 | 窗口引用、会话与媒体代次、事务超时、错误事件 | 列表、选择、加载和恢复状态 | 窗口生命周期与有效目标识别 |
| 几何 / resize（待实现） | 版本化请求、实际尺寸回执、新几何与首帧关联 | 提出可用视口和逻辑尺寸，消费实际结果，切换坐标映射 | 执行可接受的窗口尺寸，返回最小尺寸或拒绝原因 |
| 输入（待实现） | 输入消息结构、排序、时效、控制租约与释放语义 | 手势 / 键盘 / IME 转换，携带目标和几何版本 | 验证目标与权限，执行输入，维护按下状态并释放 |
| 指标与异常 | 输出含明确定义和可观测范围的状态、帧时序与统计 | 显示状态和诊断入口，不改变指标定义 | 捕获 / 权限 / 窗口不可用原因 |

后续契约至少区分主机会话、窗口引用、媒体代次、几何版本、事件序号与控制租约。几何生效后再使用相应输入映射；陈旧目标或版本不投递。上述几何、租约与输入契约是待实现要求，不是构建 8 已有能力。它们的设计和移动视口原型可并行，实机输入验收仍需 Host 支持。
