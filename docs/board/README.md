# KKRemote 任务看板

打开 `index.html` 即可浏览，无需安装依赖或联网。完整计划为 8 个阶段、41 项任务，默认展示通信与客户端两条工作线；每张卡片包含执行步骤、依赖、验收标准、交付物和已有证据。

## 使用方式

- W01 / W02 的远端目录、选窗、切换与停止观看子交付已接入构建 8，并通过 iPhone 蜂窝/Ponte 的选窗、停止重选和源关闭恢复验证。完整任务仍在进行：几何/控制边界、AX 匹配和动态原生像素尚待补齐。目标是连接、选窗、操作的产品闭环；传输压力验收作为支线保留，未通过项不会标成完成。详见 [窗口产品首版推进](../design/窗口产品首版推进.md)。
- 「通信协议研发」负责通信层研发与优化；「iOS 研发」负责客户端交互。Mac 窗口控制 / 输入执行作为待分配配合项，详见 [研发分工与接口边界](../design/研发分工与接口边界.md)。
- 左侧切换阶段，顶部切换任务看板、阶段计划或验收基线；可按负责人、关键词和优先级筛选。通信侧 T02a / b / c 已落地，接下来完成受控丢包恢复与观测开销验收；iOS 侧独立推进客户端交互，本会话不修改其交互代码。
- 点击任务后，可以勾选验收项、填写备注并保存状态。标记完成前需勾选全部验收项，实际证据应写入备注。
- 本机标记仅存于当前浏览器，不会自动写回仓库或启动任务；不同浏览器、文件打开与 HTTP 打开之间不保证共享记录。
- 「导出进度 JSON」保存计划快照和本机记录，便于回传更新；「恢复发布快照」会清除此任务的本机标记和备注。
- 报告链接依赖仓库中的相对目录。只复制 HTML 仍能浏览全部计划，但无法打开原报告。

## 更新计划

`plan.json` 是任务计划的维护入口，`template.html` 是界面模板，`index.html` 是生成产物。更新任务状态时同时补充验收证据；浏览器导出的记录需要核对后再合入计划，不能直接视作验证结论。

在仓库根目录运行：

```bash
python3 scripts/build-task-board.py
```

构建脚本会检查任务编号、状态、依赖是否存在或成环，以及已有证据文件是否有效。生成的 HTML 内嵌完整计划，后续不要单独编辑 `index.html`。

需要 HTTP 预览时，在仓库根目录运行：

```bash
python3 -m http.server 47888 --bind 127.0.0.1 --directory docs
```

然后打开 `http://127.0.0.1:47888/board/`。服务器仅绑定本机，不向局域网或公网开放。

## 状态口径

任务完成数是有记录的任务数量，不是产品完成百分比。已验证性能、试行验收门槛、后续产品目标分别标注；20 Mbps 配置上限不等于持续 20 Mbps 有效视频载荷，接收缓冲也不等于屏幕端到端延迟。

后续按任务编号推进：准备条件 → 执行 → 保存证据 → 核对验收 → 更新快照。阶段出口未满足时，保留失败或未测项，不以平均帧率代替完整验收。
