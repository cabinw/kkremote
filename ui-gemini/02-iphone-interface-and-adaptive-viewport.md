### 1.5 横屏工作区布局（Landscape iPhone）

手机横屏是查看宽表格、代码编辑器（IDE）和横版视频剪辑的黄金场景：

```text
+------------------------------------------------------------------------------+
| [Dynamic Island 避让区]     Mac 应用横向内容完整铺满 (如 VS Code / 浏览器)    |
|  (左侧安全区：自适应取色融合)                                                   |
|                                                                              |
|  > Explorer      1  import SwiftUI                                           |
|    Sources       2  struct ContentView: View {                               |
|    - App.swift   3      var body: some View { ... }               [⊞|⌨|⋯]  | <- 胶囊默认吸附右边缘中下部
|                  4  }                                                        |    避免遮挡底部滚动条或代码行
+------------------------------------------------------------------------------+
```
- **横屏自动触发策略**：当设备从竖屏旋转至横屏时，先经过 250ms 防抖；若主机支持 `ResizeRequest`，向 Mac 发送横屏工作区逻辑尺寸（如 `744×390` 或保持原生宽比 `1280×800` 根据用户偏好），等待新 `epoch` 首帧后再恢复触摸。
- **横屏软键盘防遮挡**：横屏下系统软键盘会占掉 ~55% 高度，因此横屏唤醒键盘时，优先采用「浮动半透明紧凑 IME 输入栏 + 极窄单行快捷键带」，并将焦点矩形平滑上移到上半屏可见带。

## 二、三段式智能视口引擎（超越 Casement 的核心优化）

传统远程桌面（含普通截图缩放）与 Casement 在 iPhone 上的最大痛点在于：**Mac 桌面应用往往有无法打破的最小宽度**（如 WPS 表格最小 672pt、Xcode 最小 ~900pt、Finder 最小 ~520pt）。基于已验证的 `ViewportGeometry` 与 `MobileWindowSizing`，设计如下三段式视口引擎：

### 2.1 三种视口模式定义

| 模式 | 适用场景 | 几何算法与视觉表现 | 与 Host Resize 的关系 |
|---|---|---|---|
| **1. 原生自适应（Adaptive Fit）** | 窗口最小宽度 ≤ 客户端可用宽度（如浏览器移动/窄版布局、终端、备忘录、ChatGPT/Claude 桌面端） | 客户端发 `ResizeRequest(width: viewportWidth, height: viewportHeight)`；收到匹配新帧后 **1:1 铺满**，文字与原生 iOS App 几乎无异 | Host 真正缩小窗口，无任何边缘裁切 |
| **2. 智能锚点铺满（Smart Fill — 默认推荐）** | Host 拒绝缩到手机宽度（如 WPS 固定 672pt、IDE、设计软件） | 先尽量把窗口缩小到其最小宽度/合适比例，客户端执行 **等比铺满（Aspect-Fill）** 并自动将视口锁定到**最佳初始锚点**（默认左上角，保留行号/首列/主工作区）；**无需切出操控，随时可用双指拖动视口去看右侧/底部，或用锚点预设一键跳区** | Host 维持其最小可行桌面尺寸；客户端做无损高清裁视口 |
| **3. 完整窗口全貌（Fit Whole Window）** | 需要一眼看清整个 PPT 排版、图片全景、多栏 Dashboard 的全局布局 | 保持完整画面 **等比完整放入（Aspect-Fit）**，上下或左右留边用 `WindowEdgeAppearance` 采样主色填充，黑边区域严禁误发触摸点击 | 不改变远端窗口，只改变客户端投影缩放 |

### 2.2 创新交互：视口微缩地图快窥（Overview Peek）

在「智能铺满」或「局部放大（2×–4×）」状态下，用户经常不知道“我现在看到的是整张大表的哪一块？关闭/提交按钮在哪里？”。
- **触发方式**：
  1. 双指捏合缩小超过边界阻尼继续微缩时，自动弹入「全貌微缩态」；或
  2. 在 Quick-Deck 中轻点/按住「视口锚点 / 全貌快窥」按钮；或
  3. 从画面外侧缘（如右缘）向内短滑进入快窥。
- **界面表现**：
  - 屏幕中央浮现一张占屏宽 72% 的半透明圆角窗口缩略全图（带实时低帧画面预览）；
  - 全图上覆盖一个蓝色发光矩形框，精确标示当前屏幕视口所处区域（如正在看左上 60%）；
  - 用户用手指**在缩略图上拖动或直接点按某区域（如右上角导出按钮、右下角 Sheet 标签）**，底层全屏视口实时跟随滑过去，松手即恢复精确操控！

        |      概览快窥 · 拖动蓝框定位视角      |
        |  +------------------------------+  |
        |  | +--------+  [图表区]   [导出] |  |

        |  | | A1:D18 |                    |  |     点击 [导出] 区域瞬间跳过去

## 三、画质透明化与 HDR 无界融合规范

直接回应用户对 Casement「发糊、缺 HDR、边框发白」的历史核心不满：

### 3.1 消除隐式降采样，提供语义级画质档位

Casement 静态分析已证实其手机端 cap 为 `2.0× / 4 Mbps`、平板端 cap 为 `1.5× / 6 Mbps` 且编码为 8-bit sRGB。KKRemote 在界面层将选择权交还给用户（具体能力与协商遵循 [contracts.md](../docs/design/contracts.md) 第 3–4 节）：

| 用户可见档位 | 采样与编码倾向（UI 传达给协商层） | 适用场景 | 气泡摘要展示 |
|---|---|---|---|
| **原画 HDR + Retina（默认推荐）** | 源端原生 2×/3× 像素上限（按设备预算）、10-bit HEVC Main10 PQ、高码率预算 | 阅读文档、表格、代码、修图、看 HDR 视频 | `2× Retina · 10-bit PQ` |
| **极速低延迟（Latency First）** | 适度降像素密度（如 1.5×）或 8-bit SDR，优先保 60fps 与最小队列积压 | 弱网蜂窝、高速连续拖拽/游戏/视频剪辑搓时间轴 | `流畅优先 · 低排队` |
| **省流模式（Data Saver）** | 限制码率上限（如 4–6 Mbps）、静态时降低帧率唤醒 | 移动流量包受限或长待机监控后台任务 | `省流模式 · 4 Mbps` |

### 3.2 顶部安全区与 HDR 边缘色彩融合（延续并统一构建 16 方案）

- **P010 原生色块延伸**：当接收端确认帧为 `SMPTE_ST_2084_PQ` 时，使用 `NativeWindowSwatch` 提取可见窗口上缘主色生成原生 10-bit 色块，通过同源 `AVSampleBufferDisplayLayer` 渲染至安全区背后，彻底消除构建 14 反馈的“SDR 填白与 PQ 视频灰白分层”问题。
- **状态栏自适应反色**：通过 `WindowEdgeColor.prefersLightContent`（线性亮度阈值 `0.18`）与防抖器（`>3/255` 变化且连续 2 次确认，0.25s 动画缓动），保证深色 IDE / 终端上状态栏呈白色字体，浅色 WPS / Safari 上呈黑色字体。
- **智能窄边框提示（Edge Affordance）**：在「智能铺满」存在被裁切隐藏区域的方向（例如右侧还有内容），紧贴屏幕边缘渲染一条 **1.5pt 极细渐隐内阴影/微光指示线**，不占内容空间，但在视觉上自然暗示“右边还有内容可双指滑过去”。
